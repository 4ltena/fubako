# 画像添付と注意文（CW）設計

作成日 2026年9月2日
状態 承認済み。実装計画は `docs/superpowers/plans/` に置く。

## 目的

推し活の投稿はグッズ写真とスクリーンショットが中心なので、画像を投げられないと投稿そのものが起きない。一方で画像は本文より不意打ちが強く、身バレと転載の入口にもなる。この設計は、README の三原則と「サーバ側で落とす」を画像でも守ったうえで、画像添付と、書き手が任意で付ける注意文を加える。

伏せの表示は Misskey の閲覧注意メディアを参考にした。アップロード時に blurhash を計算し、伏せた状態では blurhash だけを描き、読み手が開いたときに原画を取りに行く。Misskey が持つ nsfwjs の自動判定は持ち込まない。

## 決定事項

- 期限切れのあとも画像は本人のアーカイブに残る。本文と同じ扱いにして、可視性の約束を一つに保つ。実ファイルは投稿を削除したときだけ消す。
- 画像の伏せは投稿単位で本文と同じ判定に従う。画像だけを別に判定しない。
- 注意文は書き手が任意で付ける。付いていれば地雷宣言の有無に関係なく、本人以外の全員に対して本文と画像を畳む。
- 保存先は Vercel Blob の private アクセス。公開 URL は作らず、認証済みの API が代理で返す。
- EXIF は全て落とし、向きは画素に焼き込む。元ファイルは保存しない。

## データ

Post に `cw String?` を足す。空文字は null として扱う。長さの上限は 60 文字。

Image テーブルを新設する。

| 列 | 型 | 内容 |
|---|---|---|
| id | String | cuid |
| postId | String | Post への参照。投稿削除で cascade |
| key | String | Blob 上のパス。`images/<postId>/<id>.webp` |
| blurhash | String | 5×5 で符号化した文字列 |
| width, height | Int | 再エンコード後の寸法 |
| bytes | Int | 再エンコード後のサイズ |
| createdAt | DateTime | |

投稿 1 件につき画像は最大 4 枚。順序は作成順で固定し、並べ替えは作らない。

## アップロードの経路

投稿フォームは 1 回の multipart 送信にし、本文、タグ、注意文、寿命、画像を `POST /api/posts` で一緒に受ける。Vercel の関数はリクエスト本体が 4.5MB を超えると受け付けないため、ブラウザ側で canvas を使って長辺 2048px 以下の JPEG に縮めてから送る。縮小には `createImageBitmap` に `imageOrientation: "from-image"` を渡し、端末が撮った縦向き写真が横倒しにならないようにする。サーバは合計が 4MB を超えるリクエストを 413 で拒否する。

サーバ側の処理は `lib/image.ts` に集める。入力は Buffer、出力は WebP の Buffer と blurhash と寸法である。sharp で `rotate()` を呼んで EXIF の向きを焼き込み、`withMetadata()` を呼ばないことで EXIF を全て落とし、長辺 2048px に収めて WebP 品質 82 で出力する。blurhash は 64×64 に縮めた画素から 5×5 で符号化する。JPEG、PNG、WebP、GIF 以外は 400 で拒否し、GIF はアニメーションを捨てて先頭フレームだけ残す。

Blob への書き込みは `lib/storage.ts` に集める。`put(key, buffer)`、`get(key)`、`del(key)` の 3 関数だけを持つ。`BLOB_READ_WRITE_TOKEN` があれば `@vercel/blob` を private アクセスで使い、無ければ `.data/images/` 配下のローカルディスクに落とす。切り替えは起動時の環境変数だけで決まり、呼び出し側は保存先を知らない。

## 伏せの拡張

`lib/veil.ts` の判定に注意文を足す。優先順位は注意文、地雷宣言の順である。

1. 読み手が本人なら伏せない。
2. 注意文があれば伏せる。理由は注意文そのもの。
3. 注意文が無ければ、現在の地雷宣言の判定に従う。

タイムライン応答の伏せた投稿は、本文と画像の取得先を含めず、画像ごとの blurhash と寸法だけを含める。開いていない投稿の画像 ID も渡さない。`/api/posts/:id/reveal` が本文と画像 ID の配列を返し、画像本体は `GET /api/images/:id` が返す。この経路は会員であること、投稿が読み手に可視であることを確かめてから Blob を読んで代理で返す。応答には `Cache-Control: private, max-age=3600` と `X-Robots-Tag: noindex` を付ける。

開いていない投稿の画像 ID を渡さないのは、タイムラインの応答から画像を辿れる経路を残さないためである。読み手がタップした reveal が同意であり、そこで初めて ID を渡す。

## 表示

伏せたカードは、画像があれば blurhash を描いた矩形を本文の位置に置き、その上に理由を重ねる。blurhash の描画は `blurhash` パッケージの `decode` で canvas に書く。開くと本文と画像が出る。画像は 2 列のグリッドで、1 枚のときは 1 列にする。`img` 要素は開くまで生成しないので、ブラウザが先読みすることはない。原寸ビューアは作らず、`img` を新しいタブで開けば足りる。

投稿フォームには画像の選択、選んだ画像のサムネイル、注意文の入力欄を足す。注意文の欄は既定で空で、プレースホルダーに「注意文（任意。付けると全員に対して畳まれます）」と書く。

アーカイブでも同じ描画部品を使い、本人には常に開いた状態で出す。

## 削除

投稿の削除は今と同じく `deletedAt` を立てる論理削除にし、そのときに Image を辿って Blob からも消す。Blob の削除に失敗しても投稿の削除は成立させ、失敗はログに残す。孤児になった Blob の回収は作らない。

## 検証

- `lib/veil.test.ts` に、注意文があれば地雷宣言が無くても伏せること、理由が注意文そのものであること、本人には伏せないこと、注意文が無ければ従来の判定に戻ることを足す。
- `lib/image.test.ts` を新設する。EXIF に向きと位置情報を持つテスト画像を用意し、出力に EXIF が無いこと、向きが焼き込まれて寸法が入れ替わること、blurhash が返ること、2048px を超える入力が収まることを確かめる。
- `scripts/smoke.mjs` に、画像付き投稿が伏せ状態では本文も画像 ID も取得先も含まないこと、reveal のあと `/api/images/:id` で画像が取れること、非会員と期限切れでは 404 になること、注意文付き投稿が地雷宣言の無い読み手にも伏せられることを足す。

## 作らないもの

nsfwjs の自動判定、画像からのタグ推定、動画、原寸ビューア、画像の差し替えと並べ替え、注意文の定型文サジェスト、孤児 Blob の回収。

## 環境変数

`BLOB_READ_WRITE_TOKEN` を `.env.example` に足す。未設定ならローカルディスクに落ちる。

## 新しい依存

`sharp`、`blurhash`、`@vercel/blob`。
